Why this example uses both tags and fields

Project, Environment, Cloud Provider, and OS have one consistent meaning across rows, so they work well as structured fields. Tags are more flexible: they capture concerns that can overlap, such as production, api, worker, or database.

Keep sensitive details out

This example deliberately has no usernames, passwords, private keys, access tokens, or real server addresses. Put secrets in a dedicated secrets manager, not in an inventory table.
