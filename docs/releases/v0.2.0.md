## Scope

This release replaces the project relationship prototype with a dense local-first server inventory. It adds multi-tag records, table import and mapping, custom columns, per-cell copying, header sorting, reversible hiding, and complete English website policy pages.

## Compatibility And Migration

- SQLite migrations run sequentially from schema v1 through schema v5.
- Schema v3 adds server records, v4 migrates Purpose values into Tags, and v5 adds custom columns and values.
- Migrations retain legacy tables and records. Import operations are transactional.
- Older releases reject schema v5 rather than writing it. Back up `itgla.db` before rolling back the application.
- No production database, Redis, DNS, credential, or payment change is part of this release.

## Security And Privacy

- Desktop inventory stays in the user's local SQLite database and has no account, telemetry SDK, or cloud sync.
- Public traffic analytics minimizes referrers and stores a salted visitor identifier instead of raw addresses in PostgreSQL.
- Raw Nginx logs are retained for up to 14 days and minimized analytics events for up to 365 days.
- Public pages set no cookies. The protected administrator uses one Secure, HttpOnly, SameSite=Strict session cookie scoped to `/admin` for up to eight hours.
- Login attempts are bounded, administrator routes are excluded from analytics, and the analytics database/service remain isolated from other products.

## Rollout And Rollback

- Deploy the website and both release artifacts under `/var/www/itgla-site/releases/v0.2.0`.
- Preserve the previous `current` target as the rollback release before switching atomically.
- Abort or roll back for failed TLS/health checks, missing or mismatched downloads, inaccessible policy pages, broken administrator authentication, new Nginx errors, or any VeloWrite regression.
- Rollback changes only the ITGLA `current` symlink and, if changed, its dedicated Nginx configuration; no data migration reversal is required.

## Known Limitations

- Windows binaries are not code-signed and may trigger Microsoft Defender SmartScreen.
- Windows-native file-picker interaction must be smoke-tested on a real Windows host; parsing, mapping, transactions, Windows compilation, and prior native startup are covered separately.
- Policy pages describe the current product behavior but are not a substitute for jurisdiction-specific legal review. Review them with qualified counsel before accepting payments or materially changing data practices.
