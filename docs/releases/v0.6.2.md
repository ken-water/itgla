## Scope

Ship pending desktop simplification, table scrolling alignment, imported server/service labels, connection heading alignment, installer lifecycle and compression improvements, Linux glibc 2.35 compatibility, homepage/screenshots, friendly status-preserving error pages, and admin credential handling and loading fixes.

Imported names are resolved only for presentation; manually named services and raw database records are preserved. No new desktop schema migration is introduced relative to 0.6.1. Older workspaces retain existing automatic pre-migration backup behavior. Never replace a user's current database during installation or rollback. Before testing upgrades, copy the workspace and use ITGLA_DATA_DIR.

GitHub Actions runs only the two architecture-specific macOS packaging jobs for this release; no Windows/Linux Actions build. Existing website CI remains validation only.

Run locked Rust tests, formatting/clippy, advisory checks, full website/browser and analytics unit tests, packaging verifier tests, native archive/ABI checks, and all-seven-artifact checksum verification. Inspect current installer lifecycle evidence and smoke-launch the new Windows and Linux candidates using isolated data. The packaging refactor's lifecycle tests must not touch the installed real application.

Windows/macOS packages remain unsigned; macOS packages are not notarized. No signing identity is available. Native macOS interactive acceptance and additional Linux distributions are not claimed. Existing graph limits and session-only graph visibility are unchanged.

Create a draft GitHub release from the immutable tag, build both DMGs, combine all seven verified packages and sha256sums, then publish the release. Deploy the complete static site into a new release directory, preserving the historical downloads tree. Switch the current symlink atomically only after package and staging checks pass.

Back up the exact analytics source/web files, ITGLA Nginx virtual-host configuration, error snippets and logrotate configuration before updating them. Do not replace analytics.env, certificates, databases or other virtual hosts. Check Node syntax and nginx -t before activation; restart analytics only if its backend files changed, then reload Nginx. There is no analytics schema change.

Immediately and after a second smoke interval, check HTTPS health, version and all seven download hashes, historical checksums, sitemap/llms, clean admin URL and enabled sign-in, anonymous admin API 401, friendly 404 with actual 404 status, JSON API errors, active analytics/Nginx, and the unrelated VeloWrite site. Do not roll back or delete databases, credentials or logs.
