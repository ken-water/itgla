# Admin dashboard progressive-loading fix — 2026-11-01

The production screenshot showed a successful session with a blank dashboard after a 15-second request timeout and an unrelated favicon 404. The previous fix covered sign-in initialization and chart loading but retained a single Promise.all across all eight analytics requests. Any slow or failed request discarded every successful result, including the selected Overview tab.

Read-only production query timings for all eight report functions were 49–81 ms. An HTTPS smoke with a short-lived, randomly generated test session measured 233–299 ms, all HTTP 200. Only aggregate timing/size/status metadata was printed; the test session was removed in finally, with a two-minute expiry as a cleanup fallback. No credentials or report contents were logged. These timings exclude the user's browser/network and do not prove which individual request stalled for that user.

The dashboard now requests only the selected tab's data, renders each completed region independently and names any failed region. Overview uses summary, daily trend, top pages and recent events, leaving countries/download details until their tabs are selected. Chart readiness does not block tables or metrics. Refresh retries the selected tab. A generation counter prevents old report requests from overwriting a newly selected tab or a signed-out view. Existing authentication, 15-second request bounds and JSON-only sign-in are preserved. The admin page explicitly references the existing /assets/favicon.ico.

Validation: JavaScript syntax and scoped whitespace checks passed. Nine Chromium browser tests passed, including desktop/mobile authenticated dashboards, stalled resources, a stalled recent-events request preserving successful metrics/tables, on-demand tab requests, timeout/recovery and disabled/unavailable JavaScript submission safety. Final run: 18.3 seconds. No desktop code, schema or installers changed.

Rollout replaces only admin.html and admin.js with exact saved originals retained in a timestamped /root/itgla-admin-progressive-* directory. Node syntax, authenticated endpoint status and icon/page health are checked before accepting deployment. On failure restore both originals.
